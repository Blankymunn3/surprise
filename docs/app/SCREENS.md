# 화면 명세 — 지도 / 달력 / 사진 올리기

공간을 고른 뒤의 화면을 정합니다. 공간 목록까지의 흐름은 [SPACES.md](SPACES.md).

## 셋로그를 먼저 확인한 결과

만드는 방식을 정하기 전에 셋로그가 실제로 어떻게 굴러가는지 찾아봤습니다.
**공개된 글에서 확인한 것만** 적습니다. 앱을 직접 써 본 게 아니라 확실하지 않은 건
아래에 따로 적어 뒀습니다.

| 확인한 것 | 내용 |
|---|---|
| 함께 쓰는 단위 | **로그(Log)** 라고 부르는 단체방 |
| 만드는 법 | 오른쪽 위 **+** → 로그 이름 정하기 |
| 초대 | 이름을 정하면 **초대 링크가 바로 생깁니다.** 카톡·문자로 보냅니다 |
| 참여 | 받은 사람은 **초대 코드/링크**로 들어옵니다 |
| 인원 | 자료마다 다릅니다 — 기본 4명, 신청하면 6명, 최대 12명이라는 글이 섞여 있습니다 |
| 기록 | 알림 주기(매시간 / 3시간 / 끔)에 맞춰 2초 클립을 찍으면 하루 끝에 자동으로 이어 붙습니다 |

**확인하지 못한 것**: 앱을 열었을 때 첫 화면이 로그 목록인지, 지난 날짜를 달력으로
다시 볼 수 있는지. 이용자들이 "지난 날 거 어디서 봐?" 하고 묻는 글은 있는데
답이 되는 공식 설명을 못 찾았습니다.

### 그래서 우리가 가져오는 것 / 안 가져오는 것

| 셋로그 | 우리 | 이유 |
|---|---|---|
| 로그 = 함께 채우는 방 | **공간(Space)** 그대로 가져옵니다 | 우리가 하려던 것과 같습니다 |
| 이름 정하면 초대 링크 즉시 생성 | **가져옵니다** | 만들고 나서 "초대하기"를 또 찾게 하지 않습니다 |
| 알림 주기·2초 클립 | **안 가져옵니다** | 우리는 순간을 재촉하는 앱이 아니라 다녀온 곳을 쌓는 앱입니다 |
| 하루 지나면 흘러감 | **안 가져옵니다** | 지도와 달력은 남는 게 전부입니다 |
| 인원 제한 | 두지 않습니다 | 둘~가족 규모라 제한이 의미 없습니다 |

## 공간 안의 화면 — 상단 탭

공간을 고르면 **지도 | 달력** 두 탭이 위에 붙습니다.

```
┌──────────────────────────────┐
│  ←   우리 추억 지도      ⋯   │  ← 뒤로 = 공간 목록, ⋯ = 멤버·초대·이름 바꾸기
├──────────────────────────────┤
│      지도      │     달력     │  ← 상단 탭
├──────────────────────────────┤
│                              │
│         (탭 내용)             │
│                              │
│                        ( + ) │  ← 두 탭 모두 오른쪽 아래 사진 올리기
└──────────────────────────────┘
```

**같은 사진을 두 가지로 보는 것뿐입니다.** 지도는 *어디*, 달력은 *언제*.
그래서 탭을 옮겨도 데이터를 다시 받지 않습니다.

### 지도 탭

```
┌──────────────────────────────┐
│  [ 🔍 지역 검색            ] │  ← 위에 뜨는 검색창
│                              │
│         (전체 화면 지도)      │
│      다녀온 지역은 사진으로    │
│         칠해집니다            │
│                              │
│  [+]                         │
│  [−]                    ( + )│
│  [◎]                         │  ← 왼쪽 아래 확대·축소·내 위치
└──────────────────────────────┘
```

웹(`map/index.html`)과 **같은 배치**입니다. 검색은 위, 지도 조작은 왼쪽 아래,
사진 올리기는 오른쪽 아래. 손가락이 겹치지 않게 나눠 둔 것이라 그대로 갑니다.

지역을 누르면 → 그 지역으로 확대 + 아래에서 시트가 올라옵니다.

```
┌──────────────────────────────┐
│  서울 중구            사진 4장 │
│  ┌────┐┌────┐┌────┐┌────┐    │  ← 가로로 넘기는 사진들
│  │★   ││    ││    ││    │    │     ★ = 지도에 칠해지는 대표사진
│  └────┘└────┘└────┘└────┘    │
│  [ 대표로 지정 ]  [ 지우기 ]  │
└──────────────────────────────┘
```

### 달력 탭

**앱에 어두운 화면은 없습니다.** 폰이 다크 모드여도 화면은 밝게 둡니다 —
웹에서 이미 `color-scheme: only light` 로 막아둔 것과 같은 규칙입니다.
안드로이드의 강제 다크(force-dark)도 테마에서 꺼야 합니다.

```
┌──────────────────────────────┐
│      ‹   2026년 3월   ›       │
│  일  월  화  수  목  금  토   │
│  ┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐┌──┐│
│  │ 1││ 2││🖼3││ 4││🖼5││ 6││ 7││  ← 사진 있는 날은 그날 대표사진 썸네일
│  └──┘└──┘└──┘└──┘└──┘└──┘└──┘│
│   …                          │
├──────────────────────────────┤
│         달력 접기  ⌃          │  ← 접으면 아래 목록이 넓어집니다
├──────────────────────────────┤
│  3월 5일 · 오사카             │
│  ┌────┐┌────┐┌────┐          │
│  └────┘└────┘└────┘          │
│  3월 3일 · 서울 중구          │
│  ┌────┐                ( + ) │
└──────────────────────────────┘
```

- **지도 탭과 같은 밝은 파스텔 바탕**입니다. 위쪽에 라일락을 옅게 번지게 해
  지도 화면과 구별만 줍니다. 탭 하나 옮겼다고 앱이 뒤집히면 안 됩니다.
- 사진이 있는 날은 **그날의 대표사진**이 칸을 채우고 날짜 숫자가 위에 얹힙니다.
  밝은 사진이 와도 숫자가 읽히도록 **칸 위쪽에만** 옅은 그늘을 깔고 숫자를 흰색으로 둡니다.
- 사진이 없는 날은 **반투명 흰 칸에 숫자만**. 사진 있는 칸과 밝기가 비슷해야
  격자가 얼룩덜룩해지지 않습니다.
- 오늘은 로즈 테두리. 사진 위에 그려야 하므로 칸 배경이 아니라 맨 위 레이어입니다.
- 일요일 숫자만 로즈.
- 날짜를 누르면 아래 목록이 그 날로 스크롤됩니다.
- **달력 접기**를 누르면 달력이 접히고 사진 목록만 남습니다. 넘겨 보기 좋으라고.

## 사진 올리기

오른쪽 아래 **+** 는 두 탭에서 같은 화면을 엽니다.

```
사진 여러 장 고르기
        │
        ▼
  메타데이터 읽기 (기기 안에서, 네트워크 안 씀)
        │
        ├─ 찍은 날짜(EXIF DateTimeOriginal) ─▶ 날짜 칸 자동 채움
        └─ 위치(EXIF GPS) ─▶ 경계 데이터와 대조 ─▶ 지역 칸 자동 채움
        │
        ▼
┌──────────────────────────────┐
│  사진 3장                     │
│  ┌────┐┌────┐┌────┐          │
│  └────┘└────┘└────┘          │
│                              │
│  지역   [ 서울 중구      🔍 ] │  ← 비어 있으면 반드시 골라야 합니다
│  날짜   [ 2026-03-05     📅 ] │  ← 비어 있으면 오늘
│                              │
│  ⓘ 사진에서 자동으로 채웠어요  │
│                              │
│         [ 올리기 ]            │
└──────────────────────────────┘
```

- 고른 사진 **전체에 같은 지역·날짜**가 붙습니다. 한 번에 여러 장 올리는 건
  보통 같은 곳에서 같은 날 찍은 사진이기 때문입니다.
- 사진마다 EXIF 값이 다르면 **가장 많은 쪽**을 기본값으로 두고,
  "3장 중 2장이 다른 곳이에요" 하고 알립니다. 사진을 나눠서 올리면 됩니다.
- **지역은 비워 둘 수 없습니다.** 지도에 올라갈 자리가 없어지니까요.
- 위치 판정은 **기기 안에서** 합니다. 이미 가지고 있는 경계 데이터에
  좌표가 들어가는지 보면 되고, 그래야 사진 위치가 밖으로 나가지 않습니다.

| 플랫폼 | EXIF 읽는 법 |
|---|---|
| 안드로이드 | `androidx.exifinterface` |
| iOS | ImageIO (`CGImageSourceCopyPropertiesAtIndex`) |

둘 다 표준이라 의존성을 새로 들이지 않습니다.

## 대표사진

한 지역·하루에 사진이 여러 장이면 **어느 걸 보여줄지** 정해야 합니다.

| 어디에 쓰이나 | 무엇 |
|---|---|
| 지도에서 지역을 칠하는 사진 | **지역 대표사진** |
| 달력 칸의 썸네일 | **날짜 대표사진** |

- 기본값은 **가장 최근에 올린 사진**입니다.
- 지역 시트·날짜 목록에서 사진을 길게 눌러 바꿉니다.
- 한 장이 지역 대표이면서 날짜 대표일 수 있습니다. 서로 상관없습니다.
- 대표사진을 지우면 **그다음으로 최근 사진**이 자동으로 대표가 됩니다.

## 데이터 구조

> **지금 앱은 이 구조가 아닙니다.** 로그인이 없어 Firestore 를 못 써서, 지역·날짜를
> 사진 파일 이름에 적고 있습니다. 아래가 **목표**이고 현재 상태는 [STATUS.md](STATUS.md).

지금까지는 지역 하나에 사진 한 장(`regions/11140.jpg`)이었습니다.
여러 장이 되면서 **사진이 스스로 문서를 갖습니다.**

```
spaces/{spaceId}/photos/{photoId}
  regionCode    "11140"                             비워둘 수 없음
  takenOn       "2026-03-05"                        날짜만. 시각은 안 씁니다
  storagePath   "spaces/{spaceId}/photos/{photoId}.jpg"
  uploadedBy    uid
  uploadedAt    서버 시각

spaces/{spaceId}/covers/region_11140     { photoId }   지역 대표사진
spaces/{spaceId}/covers/day_2026-03-05   { photoId }   날짜 대표사진
```

**대표사진을 사진 문서의 깃발(`isCover`)로 두지 않는 이유**: 대표를 바꿀 때마다
문서 두 개를 고쳐야 하고, 중간에 실패하면 대표가 둘이거나 없어집니다.
따로 두면 한 문서만 고치면 끝입니다.

**`takenOn` 이 날짜만인 이유**: 달력이 하루 단위이고, 시각까지 저장하면
시간대 때문에 밤 11시 사진이 다음 날 칸으로 밀립니다. EXIF 촬영 시각은
*찍은 곳의 벽시계* 시각이므로 그 날짜를 그대로 씁니다.

**파일 이름을 지역 코드가 아니라 사진 ID로 바꾸는 이유**: 같은 지역에 두 장을
올리면 지역 코드로는 이름이 겹칩니다.

### 지금 웹은 어떻게 되나

웹은 `regions/{코드}.jpg` 한 장만 봅니다. 구조가 바뀌면 웹도 손봐야 합니다.
**앱을 먼저 만들고, 웹은 지역 대표사진만 읽도록 나중에 고칩니다.**
기존 사진을 옮기는 절차는 [SPACES.md](SPACES.md) 참고.

## 앱 구조에 미치는 영향

```
core/model/       Photo, PhotoId, RegionCode, LocalDate
domain/           UploadPhotosUseCase, SetCoverPhotoUseCase,
                  ObservePhotosByRegionUseCase, ObservePhotosByDayUseCase,
                  ResolveRegionFromLocationUseCase   ← 좌표 → 지역
data/photo/       사진 문서(Firestore) + 파일(Storage) + EXIF 읽기
feature/map/      지도 탭
feature/calendar/ 달력 탭            ← 새로 생김
feature/upload/   사진 올리기 시트    ← 새로 생김
```

iOS 는 `FeatureCalendar`, `FeatureUpload` 로 같은 이름을 씁니다.

**Store 는 화면마다 하나**라는 규칙([MVI.md](MVI.md))을 그대로 지킵니다.
탭이 둘이므로 `MapStore` 와 `CalendarStore` 가 따로 있고,
올리기 시트는 두 탭이 함께 쓰므로 `UploadStore` 가 따로 있습니다.
탭을 바꿔도 사진 목록을 다시 받지 않도록, 사진은 공간 단위로 한 번 구독해
두 Store 가 같은 흐름을 봅니다.

## 만드는 순서

1. **디자인** — 클로드로 화면을 그리고 → 피그마로 옮기고 → 피그마를 보고 개발
2. 멀티모듈 뼈대 + CI 초록불
3. 로그인 · 공간 목록 · 초대
4. 지도 탭
5. 사진 올리기 (EXIF 포함)
6. 달력 탭
7. 대표사진 · 검색

디자인이 먼저인 이유는 화면 간격·색·모서리 값을 코드에 흩뿌려 놓고
나중에 맞추는 게 훨씬 비싸기 때문입니다.
